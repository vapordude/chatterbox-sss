## $(date +%Y-%m-%d) - Optimize RwLock Contention with Double-Checked Locking
**Learning:** In the `chatterbox-rs` repository, inference modules scaling dynamic structures like positional encodings often acquire an unconditional `RwLock::write()` to check if a tensor needs expansion. In multithreaded inference scenarios (e.g., serving via a web server), this serializes all requests, leading to severe lock contention and massive performance degradation even if the underlying tensor is already adequately sized.
**Action:** When working with shared dynamically sized cached tensors in Rust `RwLock`, implement a double-checked locking pattern: first acquire a `.read()` lock to verify if the tensor is large enough, drop the read lock explicitly, and only then acquire a `.write()` lock if expansion is required.
