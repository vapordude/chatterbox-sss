## 2024-10-24 - PyTorch Autoregressive Loop Anti-Patterns
**Learning:** In PyTorch token-by-token generation paths, operations like `torch.as_tensor(scalar, device=...)` or converting Python integers to tensors (e.g., for positional embeddings) inside the loop cause severe CPU-to-device synchronization overhead and memory allocations on every step. Furthermore, using native integer scalar indexing directly on embedding weights (`weight[idx:idx+1].unsqueeze(0)`) is significantly faster than converting a Python integer to a tensor to pass through the embedding module.
**Action:** Hoist static tensor creations outside of generation loops. For positional embeddings, use native integer scalar indexing on the weight matrix when the index is a Python integer to prevent tensor creation overhead.
